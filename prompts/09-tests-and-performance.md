# Prompt 09 — Test strategy, edge cases and benchmark

Read `/AGENTS.md`.

## Skill/agent routing
Use `python-testing`, `react-testing`, `tdd-workflow`, and `ai-regression-testing` where they fit. Use `benchmark-optimization-loop` for measured performance work. Ask `code-reviewer` to inspect test gaps. Use `build-error-resolver` only for actual failing builds/tests.

## Files in scope
`backend/tests/`, frontend tests, `scripts/benchmark_pipeline.py`, `docs/testing.md`.

## Task
Build a layered test suite:
- Unit tests for parsing, validation, transformations, idempotency keys and reconciliation.
- Integration tests for full execution, persistence, audit and retry.
- API tests for upload, run, status, quarantine, lineage and diagnosis.
- Frontend tests for key user workflows and loading/error states.

Required negative cases: malformed input, missing field, null, duplicate event, schema drift, empty batch, partial failure/retry, late/out-of-order event, invalid reference, identical rerun. Add at least two financial domain-specific edge cases.

Create reproducible 100k+ synthetic data benchmark with fixed seed. Measure actual elapsed time and throughput; optionally memory. Record environment and exact command. Identify one optimization and measure before/after if practical.

## Acceptance
Tests run offline without external credentials. Benchmark results are generated by running the script, never guessed. Document known gaps and avoid brittle timing thresholds in CI.
